# 动态图形 Skill 技术横向对比分析 (Comparison)

## 1. 代码驱动 MG (GCfango) vs 传统 AI 视频模型 (Sora / Kling / Runway)

| 维度 | 代码驱动 MG 管线 (GCfango) | 概率扩散文生视频模型 (Sora/Kling/Runway) |
| :--- | :--- | :--- |
| **画面清晰度与边缘** | **无限放大矢量锐利**（SVG / WebGL / Canvas） | 像素扩散，边缘有噪点、羽化与模糊 |
| **运动确定性** | **100% 确定**，同一参数渲染 1000 次分毫不差 | 概率随机，每次生成形态不一，无法重现 |
| **修改粒度** | **毫秒级/像素级**（只需改对应曲线参数或坐标） | 只能重抽卡（Reroll）或局部重绘，牵一发动全身 |
| **文字与图表** | **完美的排版与汉字支持**，文字绝对不崩溃 | 文字极度容易乱码、错字、扭曲溶解 |
| **音画同步度** | **帧级物理咬合**（0.033s 级别），落地声恰好压在触地帧 | 画面与音效割裂，只能后期外部依赖人手剪辑补配音 |
| **算力与渲染成本** | **极低**（普通 CPU + 浏览器 30 秒出片） | 极高（依赖海量高端 GPU 云端排队） |

## 2. 与业内其他 Motion 设计 Skill 的架构对比

### 传统 huashu-motion 类 Skill 的局限：
1. **按“内容讲什么”分类**（如：产品发布会、企业宣传片、口播科普）；
2. **缺乏渲染与声学闭环**：通常仅生成剪辑提示词或建议，无法直接交付最终可播放的带音轨视听成片；
3. **缺乏底层物理公式**：容易产生线性生硬的过渡，没有弹簧反弹（Overshoot）、速度驱动形变（Squash & Stretch）。

### GCfango / mg-styles-15 的突破性范式：
1. **按“视听语言与美学工程”分类**：纯矢量（Flat Vector）、手绘逐帧（Cel Boil）、极简线条（Line Art）、赛博 HUD、玻璃拟物、国风水墨等；
2. **完整的代码执行沙盒**：浏览器就是渲染器，Python 就是编曲器，FFmpeg 就是压制机；
3. **可提炼与可复用性**：任何一个成功的视觉范例，都能被抽象为标准的四个模块：
   - `Output Spec`（分辨率、帧率、时长）
   - `Technical Route`（底层绘图选型：SVG/Canvas/WebGL）
   - `Creative Seed`（品牌/故事/角色剧本）
   - `Signature Features`（关键审美标志与色彩矩阵）
